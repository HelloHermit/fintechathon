# 博文杯申报说明：政策与研究过程修订稿

修订日期：2026年10月13日  
适用背景：信息工程学院、计算机类、大一学生；以普通个人电脑和Python为主要工具。

本稿提高政策依据、贡献定位和术语的准确性，保留原方案的三组结构及拟定规模，调整主结果的表述。全部正式样本数量、平台测评和用户效果均属于研究计划，不是已完成成果。原申报文件、问卷代码及工程代码未修改。下列“一—六”可作为申报说明；“七—九”为实施与答辩附件。

## 一、项目名称

**AI图片标识的传播可达性与来源核验研究——基于跨平台测评与大学生情境实验**

“传播可达性”在本项目中有具体含义：图片经过规定的处理和传播步骤后，原有标识是否仍可见、公开元数据是否仍可读取，以及接收界面是否向用户提供提示或来源信息。项目以这一操作定义组织分层测量。

## 二、申报摘要

我国人工智能生成合成内容标识制度已将生成端标识添加、传播端核验提示与用户发布声明相衔接。《人工智能生成合成内容标识办法》及现行强制性国家标准GB 45438—2025为相关主体开展标识活动提供制度和技术依据。[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)，[国家标准题录](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F32EA2A561F1886CD8D606513512D547) 本项目据此提出一个可直接验证的问题：在具体图片处理与传播路径中，生成端的来源信息能够以何种形式到达接收界面，而附加来源信息能否帮助用户理解标识的证据边界？

研究拟建立“文件保留—界面呈现—用户理解”的分层测评框架。工程阶段采集24张有生成记录的AI图片，在3个固定传播渠道中执行4类操作，并对6张图片进行间隔复测，分别记录像素内显式标识、元数据生成字段及平台提示的变化，形成可复查的文件台账、保留率和状态转移表。用户阶段拟招募约300名本校成年本科生，随机进入“标签加来源入口”“仅标签”和“无提示”三组，以前两组为主要比较，检验来源入口及其信息对来源证据边界理解和模拟分享选择的影响，第三组提供辅助基线。

项目的贡献定位于具体场景中的测量与证据衔接：将传播操作、标识状态和用户对证据的理解放入同一研究设计，为图片处理与传输方式、来源入口设计及校园AI使用教育提供实证参考。项目预期交付轻量测评工具、可复查数据和操作建议；不预设某种界面必然有效。

## 三、选题依据与现实价值

现行规则同时涉及文件内部的生成信息、平台向公众显示的提示，以及用户发布时的声明行为。因此，研究不能只以原图是否带有标签作为观察终点，还需要分别检查传播后文件与实际接收界面。

2026年8月发布的《个人用户使用人工智能服务安全指南》将关注生成标识、避免恶意裁剪删除以及发布时主动声明列为使用行为指引，为本项目设置证据理解和模拟保标任务提供了直接参考。该文件属于标准实践指南，不能用于证明大学生已经普遍误解标识。来源：全国网络安全标准化技术委员会秘书处。[发布通知及附件](https://www.tc260.org.cn/tc260/tzgg/202608/1586c71e2ebf4db28ed4a7651788ca87.shtml)

2026年9月发布的广播电视和网络视听领域人工智能应用安全指引进一步关注转码、剪辑和跨平台传播后的标识保留与识别。它提供行业实践参考，适用范围不能直接扩大为所有校园用户的新强制规定。来源：全国网络安全标准化技术委员会秘书处。[发布通知及附件](https://www.tc260.org.cn/tc260/tzgg/202609/ec149159dcb246268eda751eee89967d.shtml)

本项目拟回答三类实际决策问题：

- 图片使用者采用不同处理、保存或传输方式时，哪些公开来源字段和可见提示得到保留？
- 当文件标识与接收界面提示不一致时，具体变化发生在哪一步，平台是否增加了新的提示或字段？
- 在相同AI提示之外增加来源记录，能否帮助学生区分“被声明为AI生成”“能够查看来源记录”和“来源已经验证”？

这些问题的回答可以形成明确的处理与提示建议。政策关联说明研究的应用场景，实际价值则由测评和实验结果检验。

## 四、研究内容与具体方法

### 1. 建立来源明确的图片基线

拟固定3个可以正常获取原始图片的生成服务，使用8组中性场景提示词，每个服务各生成1张，共24张AI原图。保存生成记录、获取时间、下载方式、原始文件、生成页面截图和SHA-256文件指纹。

“有生成记录”与“文件自带可解析标识”分别登记。团队知道图片由AI生成，不代表下载文件一定含有原生标识。若原生元数据标识不足以支持保留测量，先缩小结论范围；如增加受控写标样本，单独标为测试材料，不与原生样本合并计算。

### 2. 固定传播路径，保存每一步证据

正式测评前确定3个具体传播渠道及客户端版本，冻结操作设置、下载方式和截图步骤。每张图片在每个渠道分别执行：

1. 直接上传—下载；
2. 普通转发—保存；
3. 截图—再次上传—保存；
4. 固定裁剪并重编码—再次上传—保存。

裁剪参数拟固定为四周各裁去10%，JPEG质量拟固定为85；截图记录设备、显示尺寸和缩放设置。这些是预设测评条件，不是针对标识位置优化的移除方法。上传时使用平台提供的AI声明功能并记录设置，不将用户声明后生成的提示误认为仅由元数据触发。

四条路径各自从原图开始；另保存截图、裁剪等中间文件，用于区分本地处理变化与后续平台处理变化。拟固定抽取6张图，至少7天后复测。由此形成24×3×4＋6×3×4＝360份终点派生文件，另保存24份原图和相关中间文件。这不是360张独立原图。

渠道若不支持某项操作，不以其他操作冒充完成：先记录不支持，在正式采集前替换渠道或收缩路径，并更新数量与计划。

### 3. 分别检查文件标识和界面提示

使用Python及公开元数据读取工具整理字段；图片中的文字或图形标识、平台界面提示由两名成员独立复核并保存截图。

| 测量对象 | 具体检查 | 必须分别记录的状态 |
|---|---|---|
| 像素内显式标识 | 图片内是否保留AI文字或图形提示，是否发生截断或不可辨认 | 存在、未见、无法判断 |
| 元数据生成标识 | 生成属性、生产者名称或编码、生成内容编号是否可解析，值是否变化 | 可解析、字段不完整、未检出、格式不支持、读取失败 |
| 传播字段 | 是否新增或改变传播者与传播内容编号等信息 | 新增、改写、未检出、无法判断 |
| 平台界面 | 是否出现AI提示、提示措辞及是否有可打开的来源入口 | 显示、未显示、界面未取得 |
| 内容凭证 | 文件是否声明凭证；工具是否支持；如实际开展验证，验证结论是什么 | 未见凭证、存在未验证、验证通过、验证失败、工具不支持 |

字段变化不自动等于损坏：平台新增传播信息与原生产者字段丢失需要分开解释。明文字段存在、内容凭证存在和签名验证成功也不能互相替代。

感知哈希只辅助核对派生文件与原图的画面对应关系，并人工检查异常；SHA-256只核对文件是否相同。二者都不单独证明图片来源或内容真实。

### 4. 计算保留率与状态转移

按标识类型、渠道和路径分别汇总。保留率的分母只包含处理前确有该类标识、处理后能够完成相应检查的样本；不支持和读取失败数量另行报告。

对元数据分别统计“生成属性仍可读”“原生产者字段保留”“原内容编号保留”，同时列出字段新增和改写情况。状态转移表以处理前后的状态计数与比例描述观察到的变化。

所有工程结论限定于测试日期、渠道版本、原始样本和操作条件。未检出公开标识不证明不存在私有水印，也不能单独构成平台违法或合规结论。

### 5. 用三组情境实验检验用户侧差异

原计划约300名本校成年本科生，随机分配至三组。使用相同的6张AI图片和6张团队实拍中性图片，每人仅进入一组，图片顺序随机。

- A组：相应AI图片显示“AI生成”标签，并提供来源记录入口。
- B组：相应AI图片显示相同标签，不提供附加来源记录。
- C组：不显示AI标签或来源入口，作为辅助基线。

AI图片在A、B组的标签内容、位置和大小保持相同；其他布局尽量一致。实拍图片不附虚假的AI标签。A组来源记录按材料真实记录展示取得方式、文件编号、相关字段与检查状态；实拍材料按实际拍摄记录说明。缺失信息写明未提供，未验证信息写明未验证。研究者设计的入口标明为实验界面，不称平台已有功能，也不使用未经验证的认证图标。

主比较为A对B，干预对象是“增加来源入口及其信息”的组合，不能把效果单独归因于一个图标或一次点击。C组的来源判断作为辅助结果；来源判断只涉及生成方式，不涉及画面描述是否真实。

### 6. 明确结果变量、样本单位和分析

主结果拟为图片任务结束后的“来源证据边界理解得分”。三组回答同一组四题，每题正确计1分，错误或不知道计0分：

1. AI生成图片也可能描绘真实存在的场景。
2. 仅有AI标签就足以知道图片来自哪家生成服务。
3. 文件未检出生成标识就可以确认它是人工制作。
4. 页面列有内容编号或文件哈希就表示签名已经验证通过。

预设正确答案依次为“是、否、否、否”。这是一项项目自编任务测验，不称成熟心理量表。先做认知预测试，检查题意、难度和是否大量满分；正式收集前冻结题目与评分。它检验证据边界理解，不等于普遍媒介素养。

次要结果包括来源初始判断、判断把握程度及模拟分享选择。分享选择分别记录“保留或补充提示后分享”“无提示分享”“不分享”，不把不分享算成丢弃标识。AI标识保留或补充选择只在6张AI图片任务中计算；实拍图片另行报告，不把实拍图的无提示分享解释为丢弃AI标识。A组入口点击仅用于描述实际使用，不把B组没有入口造成的零点击解释为核验意愿低。

分析以参与者为独立单位：12张图的回答不会被当成12名独立受试者。主要报告A、B组平均得分差和置信区间，分享结果报告组间比例差；图像重复回答先在个人层面汇总。约300人是招募目标，正式前由导师结合最小关注差异、测量质量、脱落和招募能力核定分析精度，不声称这个数天然足够。随机分组也不等于随机抽样，结果不代表所有大学生。

## 五、特色与拟形成的贡献

**第一，建立分层测量口径。** 分开记录文件内可读信息、图片内可见标识和平台前台提示，识别“文件字段改变但平台仍有提示”等情形，使指标能够反映具体操作结果。

**第二，连接工程材料与用户任务。** 以实测状态选择情境材料，再比较用户对证据边界的理解及模拟分享选择，避免只做“加了AI标签是否更容易认出AI”的重复性验证。两阶段衔接不等于已经证明传播操作通过心理机制改变真实行为。

**第三，形成可复查的低成本交付。** 工具、原始记录、操作条件、状态判定与汇总表对应保存，使其他学生能够复查和复用流程。以公开工具为测量基础，将贡献集中在统一的测量流程、明确的场景比较和工程与用户证据的衔接。

## 六、已有基础、进度与预期成果

目前已有图片标识检查和本地处理的可运行初版，以及使用示意材料的三组问卷原型。真实跨平台测评、正式刺激材料、真实参与者数据和研究效果尚未取得。工程原型还需完善字段兼容性、异常状态分类与人工复核流程；问卷还需通过目标网络访问及集中回收验收。

拟按三个月安排推进：

| 时间 | 任务 | 可检查产出 |
|---|---|---|
| 第1—2周 | 获取少量原生样本，验证一条真实路径；检查手机访问与数据回收 | 原文件、派生文件、界面记录、可实际收到的数据 |
| 第3—5周 | 冻结样本和渠道，开展主测评 | 样本台账、路径记录、人工复核表 |
| 第6—7周 | 间隔复测，整理工程结果，制作实验界面 | 状态转移表、可复查材料、正式刺激候选 |
| 第8周 | 认知预测试、回收验收和分析方案冻结 | 题目修订记录、样本目标依据、冻结方案 |
| 第9—10周 | 正式招募与收集 | 有效数据、排除记录与完成情况 |
| 第11—12周 | 分析、报告和答辩材料 | 结果与不确定范围、研究报告、操作建议 |

正式招募前确保同学能打开、填完且研究者实际收到数据，不以本地导出成功代替回收验收。若前两周拿不到可比较的原生标识或稳定路径，先缩减或调整工程对象；若招募、测量质量和回收不能支撑正式比较，保留工程成果，将用户部分明确写为探索性研究。

预期交付：

1. 一套轻量图片标识测评工具与操作说明；
2. 带原图、派生关系和界面记录的有限样本数据集，按授权情况决定公开范围；
3. 标识保留及变化的分析报告；
4. 用户情境实验结果与分析文件；
5. 图片处理、来源提示和校园AI使用的具体建议。

即使来源入口未显示明确优势，仍报告效应估计和不确定范围，并交付工程测评；不将“未显著”直接解释为完全无作用，也不将情境选择推广成真实平台传播效果。

## 七、术语与答辩时的解释

| 申报用语 | 能直接说清的含义 |
|---|---|
| 标识传播可达性 | 图片传过去之后，文件还能读到什么，接收者能看到什么 |
| 分层标识测评 | 分别查图片文字、文件字段和平台提示 |
| 元数据结构解析 | 读取并检查文件中的生成属性、生产者与内容编号 |
| 标识状态转移 | 比较同一张图处理前后哪些信息保留、改变或不可判断 |
| 文件证据台账 | 把每个文件与取得方式、操作、时间、截图对应保存 |
| 来源证据边界理解 | 知道标签或字段能支持什么判断，不能支持什么判断 |
| 随机情境实验 | 用随机分组比较预设界面，其他材料尽量相同 |
| 模拟分享中的保标选择 | 记录任务里的分享选择，不能声称观察到了实际社交传播 |

“全链路可信溯源”“来源认证平台”“数字水印检测系统”“合规认证”“揭示治理因果机制”“显著提升识别能力”等表述不写进本稿，除非以后取得对应能力与证据。

## 八、大一团队的范围缩减建议

本次正文保留原方案规模，但360份终点文件加约300人招募的负担较高。如导师认可压缩范围，可先考虑12张AI原图、2个生成服务、2个传播渠道及2条重点路径，保留A、B两组主比较；样本目标重新按测量精度和资源核定。

这是独立的范围建议，尚未执行，不与正文规模混写，也不把减少样本后得到的探索性结果当成原计划的正式验证。
