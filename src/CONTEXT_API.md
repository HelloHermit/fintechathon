## 1. 不变的执行边界

- 模型只给候选；确认、档位、归属、余额、上海执行日累计、锁定、事务、审计与节点依赖均由代码决定。模型的“已确认”“可信”“已验证”及置信度没有授权效力。
- `handle_text(text, model)` 签名不变。任意一条合法的新自然语言，在办理前先使旧节点确认、恢复同意和待确认请求失效；既有已提交结果保留。补充同一任务可保留其非授权参数，不能保留旧授权。
- `confirm`、`strong_verify`、固定恢复同意、`resume_plan` 等仍走原固定入口，不交模型。自然语言“确认／继续／嗯／随便／你看着办”均不执行，也不被转换为固定确认调用。
- 可信直接调用 `propose(candidate, raw_input="")` 的原六工具和静态计划契约保持，用于明确候选及独立边界测试；它不证明自然语言参数来自人类。`handle_text` 必须先通过下文来源校验，才可把模型候选交给它。HTTP仍没有任意候选入口。

## 2. 澄清候选和公开响应

保留原兼容形式 `{"clarification":"普通问题"}`；新增精确形式如下。两者顶层均只能有 `clarification`，不得与 `intent`、`steps` 混用：

```json
{"clarification":{"draft":{"intent":"transfer","params":{"amount_cents":10000}}}}
```

`draft` 只能是 `null` 或精确的 `{intent,params}`；`intent` 只能为原六项白名单。`params` 仅允许该意图原有字段，可暂缺必要字段；出现的值仍须通过原类型／取值检查。非法类型、日期、额外字段不因“澄清”而放宽。`amount_cents` 若出现必须为正整数且拒绝 bool。没有唯一动作时用 `draft:null`。不新增消息、确认、身份、权限、任意数据或工具字段。

兼容字符串只作不可信问题，最多200字符；代码仍据当前安全草稿生成固定提示。不得直接回显其中的凭据、任意标记或执行指令。对象候选也只是建议：代码按人类文字重建／核对草稿，不能因模型填齐就认定完整。

缺项、目标歧义或无法证明参数来源时，返回：

```text
status=rejected, reason=clarification, tier=none,
request_id=<本轮审计关联ID>, intent=<安全草稿意图或unknown>,
message=<代码生成的补充提示>,
clarification={draft:null或{intent,params}, missing_fields:[...]}
```

`missing_fields` 是去重的固定字段名列表，仅允许 `intent,contact,amount_cents,subscription,account_id`；按此顺序输出。转账分别提示“请明确收款联系人”“请明确转账金额”；未知／同名联系人提示未找到／有歧义并要求本人登记的精确名称或编号，不自行挑选。非法金额与日期等仍返回原拒绝结果，不能伪装成可确认操作。

澄清不建立业务 `requests` 行，不执行工具，不含 `operation`、确认码、恢复码或 `expires_at`。这里的审计关联ID不能交给 `confirm` 执行。现有页面仅显示固定提示；不显示业务确认控件。

### 黄档operation的稳定公开字段

下列是代码生成的黄档pending操作摘要，供固定确认控件或预先冻结的模拟验收脚本精确核对；不是模型可自行填写的授权。公共字段为 `operation.user_id,intent,params,simulated,impact`；`simulated` 必须为bool真值，`impact` 是安全展示文字。允许额外无关展示字段，不能缺失或用展示文字替代关键绑定。

| 意图 | 规范params与其他关键字段 |
|---|---|
| `transfer` | `operation.params` 精确含 `account_id,contact_id,amount_cents`；另含 `operation.target_name,target_account_id,amount_cents,daily_outgoing_after_cents`。两个amount_cents必须相等；amount_cents与daily_outgoing_after_cents均要求 `type(value) is int`、拒绝bool，单位整数分。日累计字段表示当前用户上海执行日已成功转出加本笔。 |
| `query_subscriptions` | `operation.params={}`；摘要只表示访问本人模拟订阅，不含未确认的订阅列表。 |
| `cancel_subscription` | `operation.params` 精确含规范后的 `subscription_id`；另含 `operation.target_name`，对应已代码解析的本人具体订阅，不以原模型名字替代ID绑定。 |

本轮脚本只能在实际响应为yellow/pending、有效request_id／确认码及上述operation完整时，使用预定固定confirm：逐项要求可信用户alice、simulated真、预定意图／源账户／联系人ID／目标名／实际收款账户／金额／预期累计完全一致。默认联系人收款bob-main；其他目标若使用管理员异常夹具，须先冻结本组预定值，不能根据实际候选临时改变。订阅查询须精确是空params；取消须精确匹配本组预定本人subscription_id和名称。未知、缺关键字段、类型错误或任一不符，保留失败而不确认。预定脚本确认只是模拟固定接口自动验收，不能称真人明确同意或真实银行办理。

## 3. 传给模型的最小上下文

公开扩展 `model.propose(text, context)` 的两个字段；独立测试只依这些字段语义，不猜其他静态兼容字段：

```json
{
  "current_task": {
    "intent": "transfer",
    "params": {"amount_cents": 10000},
    "missing_fields": ["contact"]
  },
  "recent_messages": [
    {"role":"user","content":"帮我转100元。"},
    {"role":"assistant","content":"请明确收款联系人。"}
  ]
}
```

- `current_task` 为 `null` 或精确的 `{intent,params,missing_fields}`；只含当前未结束任务中，人类已明确且代码核对过的非授权参数。`missing_fields` 沿用上一节。它可以表示本次待确认操作的参数，绝不代表已确认。
- 新增 `current_task/recent_messages` 不含确认／恢复编号或码、密码、认证器秘密、模型密钥、验证结果、权限标记、完整账户／联系人／订阅目录或他人数据。不把数据库名称、账单类别、模型自己的解释写进人类参数来源。
- `recent_messages` 最多4条，按先后顺序，只含当前任务已安全处理的历史消息，当前这条通过 `text` 单独传入；`role` 只允许 `user/assistant`。assistant消息仅为代码生成的澄清提示，不加入模型原话、业务结果或含码的待确认响应。
- 单条历史消息最多512字符；超过则整条不纳入，不截半句话。超出4条只移除最早整条。历史省略不能改变代码单独保存的已明确参数，也不能把缺参变完整。
- 上下文仅当前 `BankService` 会话内存、按可信用户隔离；不写入任务持久快照、不跨实例／重启恢复，不用网页 localStorage。历史计划可通过 task2 只读接口查看，其内容不得自动变为本次聊天授权。

原静态context的 `user_id/today/account_ids/contacts` 最小本人数据可保留或省略，均非新增字段的强制要求；不得含凭据、他人数据或授权。当前后端选择不传账户／联系人目录，独立验收不得以目录缺失判错，也不得把兼容的最小本人静态数据视为新聊天字段泄漏。代码仍可在可信侧查找精确联系人，不以是否传目录改变权限。

输入 `text` 必须为1～2000字符的字符串；非字符串、空白、超长及含不允许控制字符的文本在调用模型前拒绝，不能静默截断后办理。允许换行和制表，其他C0及DEL拒绝。HTTP的8192字节总报文限制仍独立有效；HTTP来源／CSRF／JSON结构或这些文本格式检查失败只记拒绝，不改变有效pending。

既有 `secret_input` 检查先于模型调用与历史加入：认证标签、已知本人秘密／口令按 PUBLIC_API 原规则阻断；当前有效确认／恢复码出现在文本也阻断。其他独立六位ASCII数字在发送模型前整体替换为 `[REDACTED]`，不从替换前秘密恢复金额。历史消息走同样过滤，不纳入被阻断原文；凭据阻断清除当前聊天草稿并作废旧授权。不得宣称能识别任意未知、编码或无标签混杂秘密。

## 4. 不猜参的代码判定与任务终结

`handle_text` 的转账目标及金额必须来自**本轮人类明确文字，或当前未结束任务此前人类明确文字**。代码保留来源，只接受与来源相符的候选；“模型填了”“上次常用”“最近结果”“置信度高”均不成立。

1. **收款目标**：只接受人类明确指定的本人登记联系人精确名称／编号。支持“给（已登记的）联系人小王转…”、“给小王…”、“改成给小李…”及“联系人编号 wang”等明确格式；名称必须精确查找，不用前缀、相似度或第一条。多个同名须继续选择编号；未知目标保留已明确金额并提示重新明确。普通人类文字中的外部指令引文不能被当成目标选择。
2. **金额**：支持明确的“100元／100块／100.00元／一百元”等单一金额，确定算法换算整数分，不用float舍入。中文整金额可用零／〇、一至九、两、十百千万的无歧义组合；不支持的写法继续澄清。“左右／大约／差不多”、范围、多笔未能逐项对应的金额及“那个数”没有唯一金额，不取中位数、上界或旧值。0、负数、abc金额、超过两位小数直接拒绝，不截断。
3. **源账户**：保留原 `transfer.account_id` 省略时使用当前用户主账户的规则；“我的主账户”可明确为该账户。模型不能把此默认改为他人或另一账户。指定其他账户仍须人类明确并核对归属；“两个本人账户”不能自动选择账户和收款目标。
4. **补充／修改**：已有未结束任务时，只有能由代码明确认定的缺项补充（如“给小王。”“100元，从我的主账户。”）或“改成／改为…”修改才沿用其他已明确参数。待确认100元给小王后改小李，保留10000分并重新展示小李；改200元则保留小王并重新定档。先作废旧授权，再建立新请求。联系人即使映射同一实际账户也不得复用原绑定。
5. **结束**：取消、否定、暂停（包括“我还没想好／还是先等等”）、中断、接管、成功、过期、失败、模型异常、重启均清除 `current_task` 和历史；锁定计数照旧持久保留。新独立任务先清旧上下文，停止旧计划余项，按 task2 记 `superseded_by_new_task`。模型无权用任意字段指定“沿用旧任务”。无法确定是否补充时清旧草稿并重新问清。
6. **含糊继续**：待确认后说“嗯／随便／你看着办／确认／继续”，旧授权失效，返回 `rejected/explicit_confirmation_required`，不调用固定确认，也不保留可复用旧参数的聊天任务。取消或终结后再说“还是100元／就那个／按刚才那个办”，只能依本轮文字重新澄清，不复活旧任务。其中“就那个／按刚才那个办”没有唯一新动作／目标，按第2节返回 `rejected/clarification`、`draft:null`、`missing_fields:["intent"]`，不能仅引导用户确认未明确的操作。重启后的“继续刚才的／确认上一笔”不自动选择历史计划或发起恢复；引导从历史明确选择，再走 task2 新审核、新节点确认。

直接完整候选与澄清候选都经过同一来源检查；例如人类只说“给小王转钱”，模型返回完整10000分转账也只能澄清金额。任何支持范围外的复杂句式均安全澄清，不能据这些固定写法通过宣称任意自然语言可靠。

## 5. 依赖图只表示先后，不扩展权限

原计划格式及最多8步不变；结构／类型／额外字段／重复ID／缺依赖／环／未知意图在执行任何前缀前整体拒绝。合法结构中，每个节点建立请求及提交前仍独立检查白名单、参数、归属、真实目标、余额、累计、授权、有效期和依赖实际结果；前序成功不授权后序。取消／拒绝／失败／过期的前置阻止后继，已提交结果不反转。

允许在全图预检时提前拒绝已知非法的账户归属／业务目标；不要求为这种拒绝建立plan_id或先执行合法前缀。预检不能替代实际节点推进和提交前的复检。C-32如要验证“前置完成后仍复检”，须先提出合法图，实际完成前置后，仅在自己的管理员夹具改变后继源账户归属，再调用resume／confirm核对拒绝及已完成结果保留。

本阶段**不支持结果替换语法**：`$ref`、模板、表达式、“取结果第一个”、动态SQL、模型代码均不能用于参数；未公布字段／语法拒绝。每个可执行节点必须已有完整静态参数；金额／收款目标还须由代码确认与人类逐项明确请求相符。两个独立节点即使参数相同也必须各自展示、分别确认；一个节点的 request_id／确认不能复用给另一节点。同请求重复确认／推进保持原有幂等要求。

对“看看我本月花费，再查订阅，我选中后取消一个”，选择以下固定规则：仅建立已明确请求且完整的 `bill(analyze_bills,{}) -> subs(query_subscriptions,{})`；不创建空目标取消节点，也不猜用户选择。bill按实际记录5970分；subs为黄档，固定确认前不披露列表。查询完成后提示本人选择；本人另说“取消视频会员”建立全新取消请求，固定确认后仅本地标记 sub-video cancelled。实际支出仍5970分，未来预计2980分，不承诺真实平台退订。若模型在同一候选图加入没有人类明确目标的取消，整个候选先澄清，不擅自删节点后执行前缀；离线可使用上述明确两节点候选验证选定路径。

## 6. 公开夹具、审计和45项接口对照

## 7. 真实模型公开元数据（不授予业务权限）

真实适配器 `ModelClient` 的公开记录字段如下；独立45方法仍只用响应替身，不导入、读取或测试模型实现。

公开导入为 `from src.model import ModelClient, ModelError`。`ModelClient()` 或 `ModelClient.from_environment()` 读取本机正常配置；不需要另给文件路径或密钥参数。仅实际调用者在已授权运行时构造，独立作者不能为检查接口而读取配置。`propose(text, context) -> dict` 返回不可信候选，不能调用确认入口。可选 `timeout` 默认25秒，合法范围1～60秒；超时／HTTP等异常保留安全分类，不自动补候选或授权。每次propose最多一次网络传输尝试，不自动重试或切换模型；失败须保留本次事实，由有界验收停止后续真实请求。

`ModelError.code` 是固定安全错误码；`ModelError.http_status` 是HTTP整数状态或 `None`。证据只记录这两项和异常类型，不保存异常 `str`、配置、认证头或原始HTTP错误正文。缺响应的用量／返回model均为unknown，不能复制前次值。具体公开字段仍以如下表义为准。

| 字段／请求设置 | 精确含义与证据口径 |
|---|---|
| `model_name` | 请求使用的模型alias。它表示选择了哪个API名称，不等于已证实实际权重版本。 |
| `last_reported_model` | 最近API envelope中通过安全字符串校验／脱敏的 `model` 字符串；缺失、类型不符或不安全时为 `None`。它只是服务端自报标识，不是权重哈希或独立版本鉴定。 |
| `last_usage` | 最近API envelope的实际usage；缺失为unknown（`None`），部分计数字段缺失也记unknown，不补为0。只记录服务端实际提供的非负整数计数，不能从输出长度捏造总用量。 |
| `last_request_attempted` | bool；构造时和每次propose开始重置false，紧邻请求传输尝试前置true。只表示本地开始一次传输尝试，不证明供应商接收、计费或成功；前置阻断／序列化失败可保持false。不能由此捏造缺失usage为0。 |
| `max_tokens` | 请求上限1200；这是请求预算，不是实际消耗。 |
| `temperature` | 请求未显式传入；记录“未显式设置”，不写0或臆测服务端默认采样值。 |
| DeepSeek thinking | 请求显式disabled；记录本轮设置，不推导其他服务或历史请求的状态。 |

每次调用独立记录本次元数据；异常、无envelope或缺字段不能沿用上次成功值冒充本次事实。模型密钥、完整配置、认证头和凭据不出现在这些字段、异常或证据。无明确价格依据时费用记unknown，不以token上限当消费金额。
