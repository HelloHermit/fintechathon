## 三条技术硬约束

**1. 金额一律用整数分（`int`），不用 `float`。**
```python
# ❌ 不要这样
price = 19.9
total = price + 9.9        # 可能得到 29.799999999999997

# ✅ 这样
price_fen = 1990            # 单位：分
total_fen = price_fen + 990 # 2980，精确
```
输出时再转成元：`f"{total_fen / 100:.2f}"`

**2. 数据库查询一律参数化，不许拼字符串。**
```python
# ❌ 绝对不要
cur.execute(f"SELECT * FROM subs WHERE name = '{name}'")

# ✅ 必须这样
cur.execute("SELECT * FROM subs WHERE name = ?", (name,))
```
**为什么**：拼字符串 = SQL 注入，测试用例 E-07 会直接打穿。

**3. 权限档位必须查表，不许让模型输出决定。**
```python
# ✅ 代码里写死的表
TIER_TABLE = {
    "query_subscriptions": "green",
    "unsubscribe": "red",
    ...
}

# 模型只能提供 key，不能提供 value
tier = TIER_TABLE.get(model_output_intent, "red")   # ★ 默认 red
```
