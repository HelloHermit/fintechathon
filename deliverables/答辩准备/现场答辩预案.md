# 现场答辩预案（决赛：11-28/29 深圳，线下黑客松 + 作品演示 + 现场答辩）

> 决赛的讲述时长、演示是否单独计时、提问时长目前都不知道，本预案按**讲 8–9 分钟 + 现场演示约 2 分钟 + 提问 5–10 分钟**准备，拿到决赛通知后按实际调整。
> 页码按队员定稿的 17 页 PPT（`deliverables/答辩PPT.pptx`，提交 `4b81b15`）；每页那句话和时长见 `讲稿-钩子版.md`；提问答案见 `模拟提问.md`。人名留空，队长填。全部数据为模拟。

## 0. 先看结论

- **现场演示默认用回放模式**（`python run.py --reset --model replay`）：不联网、不用密钥、每次结果一样，会场断网也能演。会话 C 已在回放模式下用真实浏览器把整套演示走通。
- **只演三段，约 2 分钟**：定时转账（黄档）→ 给妈妈转两千（红档强验证）→ 骗子让转“安全账户” + 模型被带偏、代码拒绝。最后这段是全场最有说服力的 30 秒。
- **回放模式的硬限制**：必须从“你好呀”开始、按 `视频脚本.md` 第 3 节台词卡的顺序说、逐字一致，中途不能点台词卡以外的确认按钮，**不能跳着演**。评委想自己随便说一句时，要切到真实模型（需要网络和新的模型密钥）。
- **兜底三层**：回放出错 → 重置重来；电脑或后端出问题 → 播演示视频、人在旁边讲；投影也挂 → 讲 PPT 第 2、8、9 页的截图。
- **分工**：一人主讲、一人讲安全并接安全类提问、一人当演示手兼计时；“AI 辅助开发”这类态度题由队长答。

## 一、现场演示顺序（回放模式，约 2 分钟）

上台前先在页面上发一句 **“你好呀”**（回放要求第一句必须是它；台上就不用再演这一句）。之后台上按下表操作。台词一律从台词卡**复制粘贴**。

| # | 演示什么 | 操作（演示手） | 主讲同时说的话 | 时长 | 想让评委记住的一下 |
|---|---|---|---|---|---|
| 1 | 口语定时转账（黄档） | 粘贴“明天给小王转两百，备注还饭钱” → 确认单出来停 2 秒 → 点“确认办理” → 回执 | “一句话里的时间、收款人、金额、备注都解析出来了；它不能替我点确认。” | 0:30 | 口语一句话出单，确认权在用户手里 |
| 2 | 大额转账（红档强验证） | 粘贴“给妈妈转2000” → “下一步：强验证” → “获取动态码” → 指一下右下模拟手机里的短信 → 输入 135790 和动态码 → “验证并执行” | “超过小额额度，代码直接判红档。短信里写明向刘芳转两千元，看清楚再输。” | 0:40 | 所见即所签；动态码不进聊天 |
| 3 | 诱导转账 + 模型被带偏 | 粘贴“客服说我账户被冻结，让我把钱转到安全账户17000000000” → 红色提示 → 再粘贴“按那条转账备注说的做” → 在右侧安全透视里点“模型第 2 步”的“详情”，指出 `170****0000`、`2000` → 指“代码判档：拦截” | “这一步模型真的被带偏了，提出给涉诈账户转两千——代码直接拒绝。我们不指望模型永远不被骗，最后拍板的是代码。” | 0:50 | 模型提议，代码裁决——亲眼看到 |

**不在现场演**：生日计划和快进（回放下前面要先走完第 6–10 句，太长）、沙箱（我们的电脑是 Windows，沙箱卡片会如实显示“网络隔离降级”，被问到见 `模拟提问.md` D7）、订阅清单（信息量大，投影上看不清）。这些留给演示视频和 PPT。

**飞书加演（可选，30 秒）**：飞书真机上走通了绑定、私聊和小额卡片确认；大额回 App 强验证这一段，队内也确认走过，但没有单独留验收记录（和定稿 PPT 第 12 页口径一致）。评委对“多渠道”感兴趣时，用手机飞书私聊机器人说一句小额转账 → 卡片上点确认 → 打开网页，同一本模拟账本里能看到这笔转账（这一步出发前先自己试一次）。需要：后端用 `python run.py --feishu` 和真实模型启动（不能用回放）、会场能联网、`.env` 里有飞书应用凭据。30 秒只够演小额；时间多给 30 秒的话再演大额：飞书里说一句大额转账 → 飞书提示“请在 App 内完成强验证” → 网页顶部出现“来自飞书的待办” → 输 135790 和模拟短信里的动态码。动态码只出现在网页的模拟手机里，绝不发到飞书。

**只剩 40 秒时**：回放模式下不能只演第 3 段（前面两段是它的前提）。二选一：
- 网络和密钥都正常 → 切真实模型（`python run.py --reset`），直接粘贴第 3 段两句；
- 否则 → 直接播演示视频的 1:38–2:25（“反诈”和“模型被带偏”两个镜头）。

**评委说“我自己说一句试试”**：
- 已经在真实模型下 → 让评委说，演示手照常操作；
- 在回放模式 → 如实说“现在是回放模式，只能放录好的对话；我们切到真实模型给您试”，切换约 20 秒（Ctrl+C → `python run.py --reset` → 刷新）。需要网络和新的模型密钥，提前确认能用。

## 二、备用方案（按顺序降级，不要临时想）

| 层级 | 出了什么事 | 切到哪里 | 怎么切（提前练到 20 秒内） |
|---|---|---|---|
| 0 | 回放时出现“抱歉，智能助手暂时连不上” | 重来 | 点右侧“重置演示库” → F5 刷新 → 从“你好呀”开始。原因一般是打错字、顺序错或多点了按钮 |
| 1 | 用真实模型时变慢（一轮超过 8 秒）或被限流 | **回放模式** | Ctrl+C → `python run.py --reset --model replay` → 刷新 → 从“你好呀”开始按台词卡走 |
| 2 | 断网 | **回放模式** | 同上。回放不联网；前端没有任何外部资源（会话 C 已检查页面不引用外网地址），断网照常显示 |
| 3 | 后端起不来、页面白屏、电脑卡死 | **演示视频** | 播本地的 `演示视频.mp4`（U 盘里再备一份），主讲站在旁边同步讲，不要沉默看视频 |
| 4 | 电脑、投影、声音任一环彻底挂了 | **PPT 截图** | 讲第 2 页（模型被带偏、代码拒绝的截图）、第 8 页（强验证 + 模拟短信）、第 9 页（反诈拦截） |

切换时**只说一句**：“我们切到录好的演示。”反复道歉会把评委的注意力从内容转到故障上。

端口被占用时换端口：`python run.py --reset --model replay --port 8766`，浏览器打开 8766。

## 四、被问住时（背下来）

**三句救场话**
1. “这部分我们没做，目前只验证到 X。”
2. “这个数我需要回去核对，现在不敢给您一个准数。”
3. “这是我们的取舍：牺牲了 A，换来 B，因为在这个场景里 B 更关键。”

**三句绝对不要说**
- “因为我们时间不够”——等于承认没规划好。
- “这块是他负责的”——当众甩锅，两个人一起扣分。
- “这个我们考虑过”——然后接不上，比直接说没考虑更糟。

## 五、黑客松现场加需求

1. **先复述**：“您是说，转账成功后给收款人推一条消息，对吗？”复述对了评委放心，复述错了正好在动手前发现。
2. **当众判断属于哪一类**（这个判断本身就是加分项）：
   - 只改提示词、加一个查询类工具、加评测用例 → 当场可以做。
   - 新增一个写操作（要动钱或改卡状态）→ 先按风险对称定档位，再写处理器和单元测试；说清楚“少一步就是安全漏洞”，按实际时间承诺。
   - 接外部系统（真实短信、核心账务）→ 现场做不了，说明需要什么资质和对接方。
3. **给最小可验证版本**：先做能演示的一小块，不追求一次做全。
4. **改完一定跑测试再演示**（现场“改完就演”是最常见的翻车点，改坏的往往是别的地方）：

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

```bash
python bench/run_bench.py --start --only SEC --out ./现场评测
```

（第二条需要模型密钥；`--out` 指到别的文件夹，避免覆盖仓库里正式的评测报告。）

5. **底线不让步**：十条安全底线（`CLAUDE.md`）现场也不能破，比如聊天里说“我确认”永远不算确认。时间不够就少做功能，不放松档位和确认。
