## 三、★ 08 只写这三块（这就是它的全部范围）

### 第 1 块 · 一条输入从进来到写日志的完整链路

**现在的问题**：这个流程**分散在三个文件里**——
- `AGENTS.md` 第九节有一张流程图（但那是讲"模型输出不被当指令"的，不是讲完整链路）
- `src/README.md` 有一张文件清单（但没有"谁调用谁"）
- `分工表.md` 有函数签名（但没有"调用顺序"）

**没有人把一条用户输入从进来到写日志完整串一遍。** 这是 08 该做的第一件事。

**要求**：

1. 用**一条具体的输入**当例子，比如「帮我把视频会员退了」，**从头走到尾**
2. 每一步标清三件事：**哪个文件、哪个函数、输入输出是什么结构**
3. **★ 必须标出两处"拦截点"的位置**：
   - 注入关键词拦截在哪一步（在意图识别**之前**）
   - 白名单校验在哪一步（在档位判定**之前**）
4. **★ 必须标出"直接拒绝"发生在哪** —— 说明它**不进入确认流程**（这是 `docs/01` 第三节那条硬规则的落点）
5. **★ 必须标出日志在哪几步写**：
   - 查询（绿色档）要写
   - 被拒绝要写
   - 确认失败要写
   - 用户取消要写

**格式**：可以是一张编号步骤表，也可以是一张 Mermaid 图 + 步骤表。**但每一步都要能对上真实的文件名和函数名。**

---

### 第 2 块 · `main.py` 的主循环结构

**现在的问题**：`src/README.md` 里对 `main.py` 的描述只有六个字——**"程序入口，命令行循环"**。

**一个新手拿到这六个字是写不出东西的。** 这是 08 该做的第二件事。

**要求**：

1. 画出主循环的结构（**用伪代码或真实 Python 骨架，不要写完整实现**）
2. **明确这三件事各自在哪一层做**：
   - 读用户输入
   - 判断这一轮是"新请求"还是"在回应上一次的确认"（★ 这一条最容易漏）
   - 输出给用户
3. **★ 必须回答一个问题**：**待确认状态存在哪里？**
   - 是内存变量、还是数据库表？
   - 为什么这么选？（提示：`docs/01` 要求"关掉程序重开，锁定仍然生效"，这条对存储位置有约束）
4. **★ 超时检查放在哪**（`docs/01` 要求待确认请求 5 分钟超时）

**★ 这段骨架的验收标准**：队友 1 拿到之后，**能照着它把 `main.py` 的空框架搭出来**，不用再来问人。

### 第 3 块 · 错误和异常怎么流

**现在的问题**：**完全没定。**

`actions.py` 里抛了个异常，是谁接住？怎么变成给用户看的话？要不要记日志？**现在三个文件里都没写，实现的时候只能猜。**

**要求**：

1. **分类**（对应 `docs/01` 第三节那三类拒绝 + 一类系统错误）：

| 类型 | 例子 | 谁负责产生 | 用户看到什么 | 日志怎么写 |
|---|---|---|---|---|
| ① 不支持的操作 | 「帮我买保险」 | 白名单校验 | 拒绝话术 + 列出支持范围 | `result=rejected` |
| ② 参数不合法 | 「金额 -100」 | 输入校验 | 说明哪里不合法 | `result=rejected` |
| ③ 越权 | 「退掉张三的订阅」 | 归属校验 | 说明只能操作本人订阅 | `result=rejected` |
| ④ 程序内部错误 | 数据库文件损坏 | 任意层 | 友好提示（**不许暴露堆栈**） | `result=failed` |

2. **★ 定一条异常处理的统一规则**：
   - 程序内部错误**不许让堆栈直接打到屏幕上**（这是给用户看的程序，不是调试脚本）
   - 但**必须写进日志**（否则出问题查不到）
   - **★ 并且回答**：如果**写日志本身**失败了，怎么办？（提示：不能因为记不了日志就把程序崩掉，但也不能假装没发生 —— 需要定一个明确的降级行为）

3. **★ 一条边界**：**不许引入 `try/except` 一把梭的写法。**要说清哪一层负责接住什么。
