## 可直接复制的 prompt

```text
先读 AGENTS.md，再读：
  spec/competition-requirements.md
  docs/00-scope.md
  docs/01-permission-tiers.md
  docs/02-user-stories.md
  docs/05-audit-log-spec.md
  docs/08-minimal-architecture.md
  src/README.md

你负责检查模型候选请求到实际执行的链路，并按当前约定直接修改
必要的架构文档；不要擅自扩大业务范围，不要替独立测试者编写验收测试。

请检查：
1. 真实模型是否只提候选意图、参数和计划；所有权限、确认和工具
   执行是否由代码控制。不得直接运行模型生成代码、SQL 或 shell。
2. 未知意图、非法参数、越权、未实现工具是否直接拒绝；查询记录
   和转出账户是否属于当前用户，其他人的白名单收款账户可被转入。
3. 转账是否使用整数分，按上海当日已成功转出总额加本次金额判断：
   不超过 100000 分黄档，超过红档；累计额与记账是否在同一事务复检。
4. 黄档是否具体确认；红档是否有代码控制的强验证，未就绪是否拒绝。
   屏显随机码不能称为多因子认证。
5. 确认是否绑定全部具体参数、5 分钟失效且只能消费一次；连续
   3 次验证失败是否锁 10 分钟，换码、换目标和重启是否不能清零。
6. 业务与成功日志是否一起提交；审计失败是否回滚本次并停后续步骤。
   日志是否只追加，拒绝与失败也有记录，原话和异常是否脱敏。
7. 多步计划是否由代码检查固定工具及依赖；失败 / 中断后是否停后续
   步骤，已完成事项是否能说明，回退 / 人工接管是否有明确边界。
8. 受限且可监控的隔离、强验证、DAG 是否分清已实现和待实现。
   不得把普通进程称为沙箱，不得把 CLI 原型称为正式 APP / IM 达标。
9. 实现者是否公布真实启动命令、公开请求 / 结果格式、两用户测试
   夹具和测试命令，使测试作者不读实现也能验收。

输出：发现的问题、实际修改、验证证据、最不确定的地方。
不确定的赛事细则写入待核对项，不能用猜测填补；目前没有实现的
命令和功能必须标为计划，不能写成已经可运行。
```

## 分工边界

队长的 Codex 负责实现和修复；队友 1 验收普通任务；队友 2 在独立对话中仅凭 `docs/01`、`docs/02` 和公开接口 / 夹具编写攻击测试，不读实现。架构检查可以审查实现，但不能因此替代独立测试。

Python 与 SQLite 优先标准库；可用必要第三方依赖，但解释用途、安装和验证。不要预先锁死大量函数签名或把全部业务硬塞入一个文件。

正式赛题待办以 `spec/competition-requirements.md` 为准，权限与行为以 `docs/01`、`docs/02` 为准；发现冲突先指出并统一文档，不能默默选择较宽松规则。
