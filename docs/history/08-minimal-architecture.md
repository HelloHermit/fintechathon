# 08 · 原型架构与执行链路

更新：2026-10-11。状态：下文保留完整设计要求；模拟业务、CLI、本机浏览器、权限/确认/审计与候选依赖图控制已实现。真实DeepSeek三方向五请求及数据库断言、两条真实依赖图样例已运行；独立66业务＋27HTTP共93项通过，六条真实异常独立复核通过。MFA模块合成43项/99子用例通过（docs/23）；真人MFA、真实受限隔离和完整补偿回退仍缺，红档拒绝。桌面三方向GUI、确认及审计查看已复演并核对数据库，证据evidence/browser-ui-validation.json。手机按用户要求待云端后测试。实际说明见src/README.md、docs/09、docs/11、docs/13，业务规则以docs/01、docs/02为准。

这套结构像营业厅：模型负责听需求和拟申请，代码负责审核、验证、办理和留回执。

## 职责边界

| 部分 | 做什么 |
|---|---|
| 交互入口 | 接收新请求、确认或取消；展示具体目标、金额、后果及真实结果 |
| 模型接入 | 调用真实模型，产生候选意图、参数和任务步骤；遇到歧义先追问 |
| 代码审查 | 检查固定工具、参数、当前身份、记录 / 转出账户归属及固定权限规则 |
| 确认与认证 | 管理具体操作的同意、过期、失败次数和持久锁定 |
| 固定业务工具 | 从模拟数据计算账单结果，办理已获授权的取消或模拟转账 |
| 数据与审计 | 可靠保存状态，只追加日志；业务改动和成功日志一起提交 |
| 执行隔离与监控 | 限制可访问资源、观察工具执行、处理超时与中断；待选型并实测 |

Python、SQLite和本机HTTP均使用标准库，未新增业务第三方依赖；必要依赖先解释安装与验证方法。已实现简单浏览器聊天窗口，CLI用于调试，不能据此宣称正式APP/IM交互已达标。文件按职责拆分，不要求全部写进`main.py`。

当前入口：`scripts/start.ps1`启动CLI，`scripts/start.ps1 -Web`启动本机浏览器服务。`src/main.py`或`src/web.py`接请求，`src/model.py`调用真实模型并校验JSON，`src/bank.py`掌握固定权限和确认、调用模拟工具，`src/storage.py`保存SQLite业务与追加审计。网页固定资源在`src/web_assets/`；公开契约为`src/PUBLIC_API.md`与`src/WEB_API.md`，独立验收据契约设计，不读业务实现。

浏览器服务只监听127.0.0.1，可信用户由启动配置固定（默认alice）；网页、聊天和模型不能改用户。密钥仅由后端读取本机配置，session只返回用户、CSRF和配置存在标记，不返回密钥或完整配置。固定HTTP端点检查Host/Origin/CSRF、正文大小和严格JSON；非法来源或格式追加拒绝审计，不消费有效pending。静态资源和数据不加载CDN、不允许跨源调用，模型和确认内容不写浏览器持久存储。27项独立HTTP证据覆盖这些公开约定；仅回环与HTTP防护不构成沙箱、生产登录或正式渠道证明。

## 一条请求怎样走完

以“给白名单里的张三转 20 元”为例，资金与账户均为模拟：

1. 代码做第一层关键词拦截；命中则拒绝并记日志。
2. 模型提出 `transfer`、候选转出账户、收款人及金额；缺少或歧义参数先要求补充。
3. 代码核对固定工具、整数分金额、本人转出账户、白名单收款人。未知、非法、越权或未实现工具直接拒绝，不进入确认。
4. 代码读取上海当日已成功转出总额，加入本次 2000 分后判档；≤ 100000 分为黄档，超过为红档。
5. 黄档展示具体内容并等待明确同意；红档由代码要求强验证，未就绪则拒绝。
6. 执行前复检账户归属、余额、累计转出额、锁定及确认；若档位变高，重新要求所需验证，不能复用较低档确认。
7. 固定工具在同一事务内复检累计额、办理转账、消费确认并写成功日志；提交后才显示成功。

每一步的待确认、失败、拒绝、取消、超时和成功都追加日志。不能执行模型生成的代码、SQL 或 shell。

订阅查询和取消按目前摘录为黄档，细则仍待核对；查询不得提前泄露结果，取消后保留历史账单。账单分析由代码计算已发生收支，不能混入预计续费或让模型编金额。

## 待确认与失败锁定

- 每名用户最多一个待确认请求，绑定用户、动作、唯一目标和全部参数，5 分钟失效。
- 取消、换目标、改参数或新请求立即使旧确认失效；成功后只能消费一次，重复提交不能再扣款。
- 会话结束 / 重启后旧待确认失效；业务数据、验证失败次数及锁定时间保存在 SQLite，不能随启动重置。
- 失败计数按用户和操作类型保存；连续 3 次失败锁 10 分钟，换码、换目标、取消和重启都不清零。
- 验证成功或锁定期满才清零；锁定中请求直接拒绝并记日志。
- 红档候选为密码加独立手机认证器，实施方案需独立验证。屏显随机码只能表达确认，不能当成第二种认证因素。

## 多步计划怎样控制

DAG 就像先查资料再办理的清单，箭头表示哪个步骤必须先完成。真实模型可以提出步骤，代码只接受已实现的固定工具和合法依赖，检查循环、数量与参数。

每个修改步骤都独立审查和取得所需确认；不能因为用户同意整个计划就跳过具体转账确认。未完成前置步骤、工具失败、用户中断或验证失败时，停止依赖它的后续步骤。

中断后显示已完成 / 未完成步骤；可撤回的本地改动按明确策略回退，不能把反向转账当成自动回退。需要进一步授权的补救交给人工接管，并记录全过程。

当前两条真实模型图样例已验证：账单成功后订阅等待确认，人工接管使旧确认失效；余额查询成功后模拟转10000分等待确认，确认成功再查余额，并拒绝重放。候选图的非法依赖、中断、取消和失败停止另有独立离线测试。计划只留会话内存，重启不恢复旧图授权。证据为`evidence/real-model-plans.json`（两次真实请求，1583 tokens）和docs/09，不证明任意复杂规划或完整补偿。

DAG、中断/回退与人工接管、强验证、受限可监控隔离仍是正式要求；当前图控制和部分中断/接管已实现，完整补偿、MFA及真实受限隔离尚缺。未做不能写成“已支持”；普通子进程不能自动证明隔离成立。

## 保存与故障

各层捕获自己能解释的故障：模型层处理超时和非法输出，业务层处理数据冲突，审计层处理保存失败。入口把结果变成用户看得懂的说明，不能一概吞掉错误后假装成功。

业务修改与成功日志同事务提交。日志失败则回滚本次改动并停止后续处理；若早前步骤已提交，必须说明哪些已完成，不能声称整个计划都未执行。日志细则见 `docs/05-audit-log-spec.md`。

启动命令、公开接口、两名用户的测试夹具及测试命令已公布于`src/README.md`及公开契约，让独立测试无需阅读实现也能验收。最新真实正常复跑五请求3960 tokens：账单5970分，退订保持历史/未来2980分，10000分转账一次、余额990000/500000/110000分；六条真实异常另有五次服务返回4007 tokens和一次输入层预阻断，分别见evidence与docs/13。历史认证、网络、过度澄清、拒绝目标审计和HTTP失败保留，不用最新通过覆盖旧问题。
