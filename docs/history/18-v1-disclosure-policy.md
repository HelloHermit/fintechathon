## 七项疑问的处理

| 疑问 | 建议采用的工程口径 | 依据与限制 |
|---|---|---|
| 历史流水能否归纳重复付款平台 | 允许展示本人过去已发生的付款商户、金额和时间；有足够历史证据时可称“疑似周期性支出”。不能据此断言当前仍订阅、已取消或下次必扣多少钱。需要当前状态、清单、未来合计，必须黄档 query_subscriptions 明确确认。 | 权限第2、7节；US-03/04/29。只有一笔付款不能编造“每月重复”；当前原型不因此获得六个月自动归纳能力。 |
| 流水是否含失败、scheduled 记录 | 允许返回符合用户及日期范围的失败、计划记录，必须保留真实状态；不能混入已发生实际支出。本轮不新增“必须返回所有状态”的验收要求。 | US-02/03；公开 transactions.status 和干扰夹具。账单计算与流水列表分开核对。 |
| subscription_id 是否受保护 | 从当前库查出的订阅 ID 属于订阅记录，不能经绿档列出。用户主动输入的候选 ID/名称不证明库中存在。取消待确认可展示绑定本次具体操作所必要的目标，不能借此附带整份清单。 | 权限第4节；US-04/05。候选输入、具体取消目标和当前清单是三个不同范围。 |
| 查询 pending 可否含条数或总金额 | query_subscriptions 未确认时只说明访问本人模拟订阅、影响和有效期；不提前给出真实条数、清单、状态或未来合计。 | 对“确认后读取”的细化，不要求隐藏其他合法操作本身的金额。 |
| 确认后可否列已取消记录 | 允许列出已取消项，但清楚标注状态；未来合计排除取消项。不强制现有界面必须列出所有已取消项，也不删除历史付款。 | US-05/29；允许范围与强制功能分开。 |
| future_expected_cents 是什么 | 补明为本人当前 active 订阅记录的 amount_cents 合计，即当前有效登记安排的金额汇总。取消项排除，不加入 transactions 中的次月 scheduled 记录。 | 这是字段口径，待实现者核对，不是准确下月扣款预测。当前数据缺少完整扣费周期、到期日和实际平台状态；不能宣称日历预测或真实平台保证。新初始夹具5970分，取消视频后2980分。 |
| categories 可否出现平台名 | 分类键来自所选历史账本的 category，可含平台名称；不能拼入当前订阅状态或未来金额。 | 公开账单/交易字段约定；历史支付名称不因相似于订阅名而被禁止。 |

以上不会新增预测工具或放开权限。其中“当前记录 ID 的范围”“查询 pending 的数量保护”“未来合计的精确计算口径”是需要补明的细化，不能声称原文逐字规定。与主办方后续明确通知冲突时，按新通知核对和调整。
