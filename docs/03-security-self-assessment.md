## 3. 三条不能用文档代替实现的要求

**屏幕上的 6 位确认码不等于多因子身份验证。** 它最多帮助表达对本次操作的同意，不能证明独立身份因素。原型不能完成强验证时，红档保持拒绝；不能宣称已达到正式赛题强验证要求。

**固定工具名单不等于沙箱。** 项目禁止运行模型生成的代码、SQL 和 Shell，仍需按正式赛题完成受限、可监控的隔离执行并实测越界。普通异常捕获也不是沙箱证据。

**固定“查—确认—执行”流程不等于动态任务规划。** 正式版本需证明真实模型规划、依赖校验、实际执行、中断、回退与接管。原型缺少时明确记录为赛题缺项，不能用“场景不适用”消除要求。

## 4. 审计与身份的实际边界

只增不改指业务接口只能追加日志。对本机数据库文件有管理权限的人仍可能修改或删除文件；防篡改能力需要另外实现和验证，不能声称“日志绝对无法篡改”。

演示身份可以采用预置用户和固定会话，并用两份用户数据测试隔离。它证明模拟账户的归属检查，不证明生产身份系统、真实银行授权或真实支付安全。

日志设备整体故障时，系统可能无法持久化本次失败记录；必须停止业务、提示故障并保留可取得的诊断，不能声称所有故障均已有持久日志。
