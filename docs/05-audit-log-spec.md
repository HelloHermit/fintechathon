# 05 · 审计日志规格

更新：2026-10-11。状态：追加审计与原子业务事务已实现，独立66项业务＋27项HTTP验收见docs/09；真实三方向与六异常日志已由独立复核者检查，见docs/13。LA-06拒绝目标缺项已修复，新增三项独立回归与真实复跑通过，旧失败保留。队友2人工验收尚未提供。日志整体不可写时停止当前会话，不能承诺失败记录均已落盘。

日志像办理手续时留下的回执：成功要留，拒绝和失败也要留。它记录实际经过，不证明模型一定理解正确。

## 字段约定

当前表名为`audit_log`；公开字段及查询方式已公布于`src/PUBLIC_API.md`、`src/WEB_API.md`和`src/README.md`。下表仍为验收字段约定。

| 字段 | 内容 |
|---|---|
| `id` | 不重复的递增记录号 |
| `timestamp` | 带时区的时间；累计转出按 `Asia/Shanghai` 的日期计算 |
| `request_id` / `step_id` | 关联同一请求及其任务步骤，单步也必须有请求号 |
| `user_id` | 当前操作人，不信任用户输入或模型自称的身份 |
| `raw_input_redacted` | 脱敏后的原话；不要保存认证凭据 |
| `intent` | 通过白名单的意图；未知请求写 `unknown`，不能伪造为受支持操作 |
| `tier` | `green` / `yellow` / `red`；判档前拒绝用 `none` |
| `params_redacted` | 必要的目标编号、整数分金额等安全参数 |
| `event` | 收到请求、判定、待确认、验证失败、取消、超时、执行、中断等事件 |
| `result` | `pending` / `success` / `rejected` / `failed` / `cancelled` / `expired` / `interrupted` |
| `reason` | 拒绝或失败的代码及简短说明；其他状态按需填写 |

不设 `confirm_code` 字段。密码、API 密钥、认证器秘密、有效验证码均不得入库，原话、参数和异常信息也必须脱敏；只记录验证是否通过及失败次数。

当前原话整体省略；候选拒绝也保留其固定意图白名单中的非秘密目标和整数分金额，例如不存在的subscription_name，不能因拒绝而丢失全部定位参数。这只是审计候选，不能当成接受或授权。额外认证字段及未知意图的任意参数不保存；含秘密标记、六位数字、控制字符或超过80字符的文本参数脱敏。独立回归包含额外凭据字段及有效码藏入目标的情形；这些有限格式检查不证明所有未知秘密格式均已覆盖。

## 只追加与完整记录

- 应用只允许追加日志，不提供修改、删除或清空入口；可用数据库规则拦截应用的修改与删除。
- 查询、分析、待确认、成功、拒绝、失败、取消、超时、锁定、中断和人工接管都要记录。
- 未知意图、非法参数、越权、注入拦截、模型超时 / 非法输出及未实现操作都记录拒绝或失败。
- 本机HTTP非法来源、CSRF、格式、方法和未知路径也记录拒绝；不把网络层拒绝当成新业务授权，不消费或改变原有效待确认请求。
- 模型提出的计划与代码实际接受 / 执行的步骤分开记录，不能把“模型建议执行”写成“已执行”。
- 重启不能清空旧日志；测试重置必须使用独立测试数据库，不能清空普通运行日志。
- 不向用户展示内部堆栈或认证凭据。调试信息同样需要脱敏。

## 提交与故障规则

业务改动与成功日志像办理手续和盖章，必须同时完成：

1. 开始事务，复检权限、余额、累计转出额及确认状态。
2. 修改业务状态，并追加本次成功日志；转账扣款、入账、累计统计及确认消费必须一致。
3. 一起提交成功后，才向用户报告执行成功。
4. 任一保存失败就回滚全部本次业务改动，停止当前任务和后续业务处理。

拒绝或验证失败也须可靠保存日志；失败计数 / 锁定更新和对应日志应一起提交。日志写不了时，明确提示“审计不可用，已停止处理”；如有已提交步骤，逐项说明，不能笼统声称整个任务没有执行。

数据库本身无法写入时不能承诺审计完整。可以输出不含秘密的故障提示，但不能因记不了日志继续办理，也不能用另一张临时日志掩盖缺失。

## 独立验收要检查什么

测试作者仅看 `docs/01`、`docs/02` 和公开接口 / 夹具约定，不读实现。以下项目需反映在需求及测试清单中：

- 运行成功、拒绝、失败和取消请求，检查每种结果都有对应新记录。
- 保存旧日志快照，再运行操作和重启，旧记录内容不变、数量只增加。
- 请求删日志被拒绝；账单分析不能篡改历史账单，退订也不能删除历史支出。
- 提交认证内容后检查日志中没有秘密；通过公开测试约定模拟审计故障，检查业务回滚并停办。
- 单笔与多步执行结果逐项可追溯；失败后未执行的步骤不得记成成功。

意图、档位和限额唯一业务依据是 `docs/01-permission-tiers.md`，本文件不另设第二张权限表。

## 能证明到什么程度

应用只追加和独立测试通过，不能阻止电脑持有人直接改 SQLite 文件。数据库访问控制、防篡改证据及正式环境的日志保护仍需按赛事要求落实；未完成时在材料中如实标注。
