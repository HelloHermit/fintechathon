## 核实中发现、需要改口径的地方（已写进 PPT 清单和讲稿）

1. **PPT 第 9 页 / 旧视频字幕“在调用模型之前就拦下”说过头**：决策链实际是“反诈预检标出涉诈号码 → 模型照常被调用并提出 transfer → 代码判档拒绝（risk_listed）”。正确说法：“调用模型之前，代码已把该号码标为涉诈；之后模型提出的任何转账都被代码拒绝”。
2. **演示里“按那条转账备注说的做”是被风险名单拦下的**（模型顺着上一句诈骗话术提出向 170****0000 转 ¥2,000），不是被参数溯源拦下的。讲稿和视频口播按事实说。
3. **PPT 第 2 页“没有旅行场景”已过时**（会话 A 10-31 16:00 加了出境游，但没有 eSIM，也没进 151 条评测）。
4. **首轮评测安全类 17 条失败全部是第一步就收到 HTTP 429（限流）**，不是 16 条：`bench/reports/history/20261030-220340.json` 里 17 条失败用例第 1 步都是 429，那一轮全局泄露违规 0。
