## 接管后的代码审阅与修复

根代理和代码审阅代理读过实现。审阅代理仅使用Mock或内存库做开发复核，不读新独立测试，不访问正常库、不调用模型、不输出凭据。实际发现及修复如下：

| 缺陷 | 修复 | 开发复核实际结果 |
|---|---|---|
| 初始化/迁移异常没有显式释放数据库连接 | 捕获初始化异常，关闭连接后原样抛出；迁移自身回滚 | Mock连接关闭调用由0变1，原异常继续传播 |
| 最初未过期，但因素计算或审计期间跨期限仍记通过 | 因素后和提交前复查；成功元数据置于保存点，跨期全部回滚后记expired | 过期、不消费时间步、原失败数2保留，确认/验证成功日志回滚 |
| 裸已登记口令或认证器秘密误贴聊天，被送模型 | 常见误贴检测与明确识别范围，详见22/PUBLIC_API；不存口令明文 | 合成裸因素均未调用记录型模型 |
| 口令误填订阅名称等白名单参数，被拒绝但写进审计 | 审计字符串字段使用相同已知秘密脱敏 | 合成口令未进入审计参数 |
| 32位十六进制口令误填无效请求编号，被回显/记录 | 已知本人因素不作为无效确认回执/审计编号，换新编号 | 合成口令未进入审计编号或响应 |

以上复核均退出0，没有独立黑盒通过结论。正式自动结论由未读实现作者另记[23 · MFA独立合成验收](23-mfa-independent-acceptance.md)，真人验证由队长记录，不能相互代替。

## 开发与独立验收前先统一三处

| 项目 | 当前公开文字 | 建议明确的行为 | 应更新的位置 |
|---|---|---|---|
| 同请求重复验证的计数 | MFA §5、§9说同请求重放按验证失败计；§4.1、§7又说已终结请求返回 invalid_confirmation、不计失败 | 建议先检查请求有效性：已终结的原请求重复提交拒绝、不增计数；在另一个有效 pending 请求中提交已成功使用的码，则按验证失败计。两种都不执行业务，不能复用授权。若采用另一计数顺序，须把各处文字统一后再验收。 | MFA §5、§7、§9及 PUBLIC_API 的重放说明 |
| 重放表与动态码保密 | PUBLIC_API 说动态码仅在内存、不进数据库；同时公布 strong_auth_replay.code，尚未说明该字段保存什么 | 不保存原始有效动态码。公布防重放记录的存储形式、用户与时间步范围，以及成功验证和记录作废如何原子保存；可以采用不暴露原码的时间步记录等标准机制。不能把未定义的 code 字段默认为可存明文，也不能在证据中打印原码。 | PUBLIC_API 表字段、MFA §5和§8 |
| 红档明确同意与因素验证 | 权限 v3要求“明确确认 + MFA”；新契约让红档 confirm 拒绝，但未说明 strong_verify 是否同时表达对已展示操作的明确同意 | 保留 v3要求。可明确：用户先看到本次用户、动作、账户/目标、金额、影响、有效期，再由本人在认证专用入口提交两因素并明确确认这一操作；例如入口按钮说明“验证并确认本次操作”。模型不能判断同意，验证不能给其他请求授权。不要仅用“已验证身份”代替本次操作同意。 | MFA §3、§4、PUBLIC_API、实际认证入口说明 |

这些是由契约文字发现的分歧，需实现者统一规则并公布，不需要让队长选择算法或回答技术题。规则统一前，独立验收把有冲突的具体断言标为待契约；可继续准备无争议用例。

## 另两项在实现时一并公布

- 本地登记 `--reset` 的授权与影响：谁可以重置、是否使旧 pending 失效、如何记录审计。既有“同用户同操作三错锁十分钟”不能因重登记或重启清零；重放记录跨重启的规则也须明确。真人登记由队长在本机操作，独立测试只用临时库合成凭据。
- 密码散列的登记迭代次数与下限、认证器秘密的本地保存边界，以及非法/损坏登记行的处理。当前可确认是本机模拟环境，不能据此宣称具备生产身份认证或抵抗本机管理员读库的能力。不能为让测试通过增加绕过验证入口。
